# Roadmap

## v0.1 — calculation contract

- Correct EV, gross return ratio, net ROI, loss probability, and coverage.
- Skinport documented API adapter with retries and timestamps.
- Fixed-input unit tests and a static research-result page.
- Public methodology, limitations, and AI contribution statement.

## v0.2 — live case pipeline

- [x] Add a version-pinned community case catalogue and label its provenance.
- [x] Join exact market names from the catalogue and filter Souvenir variants.
- [x] Split StatTrak per eligible item.
- [x] Refuse mixed source, currency, or price type.
- [x] Report overall and per-rarity missing-price coverage.

## v0.3 — complete coverage and a page that shows real output

- [x] Add a Steam Community Market adapter so the illiquid rare-special tail has
      prices at all.
- [x] Value each case against both venues separately and report them side by
      side instead of blending or picking one.
- [x] Replace the two theoretical wear densities with observed per-grade sales
      volume, keeping uniform as a declared fallback and reporting how much
      probability mass rests on each.
- [x] Cache observations on disk with their original timestamps so a report does
      not re-crawl a provider and a stale snapshot stays visibly stale.
- [x] Allow bounded observation-time drift inside one crawl and record its span.
- [x] Feed the published page exclusively from calculated output; delete the
      illustrative figures that no code produced.
- [x] Declare Brotli as a hard dependency and stop reporting a compression
      failure as a JSON parsing error.
- [x] Price cases in bulk so a run costs tens of requests rather than hundreds.
- [x] Rank cases by observed trading volume and value the busiest first, so a
      partial run is a choice rather than an arbitrary truncation.
- [x] Cut the page to a results table, the formulas, and the sources.
- [ ] Manually audit every ordinary and rare-special outcome for the first 3-5
      cases, starting with the hand-curated rare-special pools.
- [ ] Re-verify the 2017 probability disclosure against the current build, or
      state prominently that it could not be re-verified.
- [ ] Replace the configured key price with an observed one.

## v0.4 — the question this project has not answered

Everything above measures opening a case, which is reliably negative and
therefore not an interesting result. The unanswered question is whether an
unopened case appreciates.

- [ ] Collect genuine time-series observations; do not reuse the legacy
      synthetic series. Steam exposes historical price data suitable for this.
- [ ] Pre-register a simple hypothesis relating value-to-price measures to
      future case returns.
- [ ] Compare against simple baselines in chronological train/test splits.
- [ ] Include fees, missingness, sensitivity analysis, uncertainty, drawdown,
      and failure cases.

## Publication gate

Before the first tagged release:

- revoke the legacy CSFloat key that was embedded in local source (the files now
  read an environment variable, but code removal does not revoke the
  credential);
- run secret scanning and all tests;
- verify provider attribution and data redistribution terms;
- confirm the published page's data file was generated by the pipeline and
  carries a real observation timestamp;
- record which parts the user designed, verified, and can explain, and which
  parts used AI assistance.
